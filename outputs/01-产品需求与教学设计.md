# LOW END LAB · 贝斯乐理学习 Agent

版本：0.1 / 2026-11-07。本文是产品假设、教学设计与实现建议；不是经过用户访谈验证的市场结论。目标用户来自本次需求：约两年演奏经验，能够跟谱弹奏，希望独立理解歌曲并设计贝斯线。

## 1. 产品承诺

拿起一把琴、选一首歌，从一个短段落开始：听出结构，确认和弦，把和弦音映射到指板，编出可演奏的两小节，再把它放回整首歌。

成功不是看完多少课程，而是能在一首未练过但难度相近的歌里，解释自己的落点、保住节奏并做出有意图的变化。

默认：中文、桌面/平板优先、四弦标准调弦、流行/摇滚/基础 funk 起步。风格、左右手、品数和调弦可配置。示例为原创教学练习，不冒充任何真实歌曲扒谱。

## 2. 贝斯的特殊需求

“贝斯需要的乐理弱于键盘/吉他、强于鼓手”不宜成为课程依据。不同乐器的知识重心不同，而且受风格、角色和水平影响。鼓手对节奏、曲式与乐句结构的要求可以非常高；贝斯手可能较少同时按出复杂和弦，却必须理解自己一个低音怎样改变整体和声。[S01][S02]

| 特点/痛点假设 | 对实际演奏的影响 | 产品响应 | 如何验证 |
|---|---|---|---|
| 能背 TAB，不能解释音符 | 换调、换歌就失去依据 | TAB、音名、和弦级数联动，同一句移调 | 不显示 TAB，能否找到另一调的根/五度 |
| 把会音阶当作会编配 | 调内音并不总是理想落点 | 先根音与和弦音，再解释经过音 | 对比相同节奏的两条线并解释差异 |
| 只看音高，不看音长 | 和鼓点不贴合，休止处拖音 | 音头、音尾、休止与鼓点同屏 | 同音高、不同音长的 A/B 听辨 |
| 容易丢段落或漏换和弦 | 加花回来找不到第一拍 | 乐句计数、提前一小节提示下一和弦 | 隐藏提示后完整走两轮 |
| 加花靠套形状 | 抢人声、赶拍、不能解决 | 从下一目标音反推最后两拍 | 加花后是否准确回到目标 |
| 低音当成根音 | 忽略转位或斜线和弦 | 分开显示 chord root 与指定 bass | 比较 C 与 C/E 的听感和处理 |
| 手型与理论脱节 | 知道音名但移动太远 | 同音异位、近把位优先、可换指法 | 同一句选择两个可行把位 |
| 听不出分析是否可靠 | 把错误和弦学成规则 | 候选、待确认、来源和修改记录 | 能否定位并修正预置错误 |

这些痛点需要访谈确认。首轮招募 6–8 名演奏 1–3 年的贝斯手，分别覆盖“照谱型”“耳扒型”“乐队型”，再邀请 2 位教师评审。让用户带一首熟悉的歌，观察其自然操作，不先讲产品答案。

## 3. 教学原则

1. 每轮只增加一个可听见的变量：先根音和节奏，再加五度，再改音长，最后加入连接。
2. 每条建议都带“当前语境 → 可选做法 → 听感原因 → 琴上位置 → 试弹任务”。
3. 区分定义与风格建议。“小三度相差 3 半音”是定义；“此处第一拍先落根音”是本练习策略，不是普适禁令。
4. 非和弦音不自动判错。判断其位置、时值、解决方向和风格；延留、切分、预先进入下一和弦都是可能的音乐行为。
5. 先听、再猜、后解释。默认展示简短提示，详细理论和来源折叠。
6. 没有录音也可学习。学生可跟弹、自评、选答案；没有音频输入时，Agent 不说“我听到你弹错”。
7. 趣味来自声音与创作：限制条件挑战、同句三种演法、留白挑战、呼应游戏、逐步隐藏提示。连续签到和积分不是核心。

## 4. 一次 15 分钟学习闭环

| 时间 | 用户行为 | Agent 行为 | 留下的学习证据 |
|---|---|---|---|
| 0–2 分钟 | 选歌、设调弦，选想练的段落 | 确认可用音源、BPM/拍号/和弦是否已知 | 一段已确认或待确认的素材 |
| 2–4 分钟 | 跟音乐数小节，标主歌/副歌 | 提示变化线索，不仅输出标签 | 段落标记与置信状态 |
| 4–6 分钟 | 点当前和弦，找根/三/五/七 | 指板高亮，播放音程对比 | 能解释两个落点 |
| 6–9 分钟 | 用根音编两小节 | 先固定节奏与音长，允许休止 | 可播放的版本 A |
| 9–12 分钟 | 最后半拍加连接，进入下一和弦 | 对比有/无连接并说明解决 | 可播放的版本 B |
| 12–15 分钟 | 隐藏部分提示跟弹、自评 | 给一条优先修改建议和下一任务 | 学生判断、版本、复习目标 |

## 5. 示例：Night Pocket（原创练习）

4/4、92 BPM、A 小调语境；每小节一个和弦。主歌循环 Am7–Fmaj7–Cmaj7–G7，副歌改用 Fmaj7–G7–Am7–Am7。这里的示范结构不是识别任何商用录音的结果。

两小节任务：Am7 → Fmaj7。先在 Am7 小节演奏 A1，加入 E2；下一小节第一拍落 F1。在前一小节 4& 放一个短 E1，以半音向上进入 F1。E 同时是 Am7 的五度，因此此处既是和弦内音，也是目标 F 的半音下邻接音。不要把这例子错误解释成“必须使用调外音才算连接”。

对比任务：保持音高不变，把末尾 E1 拉长与缩短分别试听；再把 4& 换成休止。让用户选择更适合当前鼓点的版本。原型中的建议基于所选示例，不代表对真实演奏的分析。

## 6. MVP 功能与验收

| 优先级 | 功能 | 验收条件 |
|---|---|---|
| P0 | 歌曲项目与手动曲式/和弦输入 | 可保存 BPM、拍号、段落和按拍变化的和弦；未知和弦可留空 |
| P0 | 小节循环与变速练习 | 清晰显示循环边界、当前小节和下一和弦；变速不改变训练音高 |
| P0 | 和弦/指板联动 | 全指板结果由确定性模型产生；调弦改变立即重算；空弦正确 |
| P0 | 两小节编配 | 音符、休止、时值、指法可编辑；播放、撤销、A/B 与保存 |
| P0 | 情境教学 Agent | 每次只给一个行动任务；事实可溯源；不确定性可见 |
| P0 | 无录音自评 | 可完成学习闭环；反馈明确标记为自评/示例反馈 |
| P0 | 版本与恢复 | 刷新后恢复；修改和弦后旧编配标记待复核，不静默覆盖 |
| P1 | 音频辅助分析 | 节拍、段落、和弦均可人工修正；低置信拒答而非硬猜 |
| P1 | DI 录音反馈 | 先校准输入延迟与信噪比；评估音头/音长/落点，保留拒评 |
| P1 | 记忆与复习 | 按实际任务表现更新掌握度；跨歌曲迁移复测 |
| P2 | 分轨、风格、多调弦与五弦 | 权限、模型质量、音域与指法适配单独验收 |
| P2 | 自由 jam 陪练 | 在已确认结构中淡出提示，根据用户目标给多种方案 |

MVP 支持“用户提供和弦谱 + 音频”或“跟 Agent 手动建立简化和弦草图”。任意歌曲的可靠自动扒谱不应成为第一版承诺。仅有一把琴和一首歌可以进入学习流程；系统无法可靠识别时必须允许听辨引导和逐步确认，而不是卡住整堂课。

## 7. 页面、流程与异常

一级入口：我的歌曲、练习工作台、指板实验室、学习记录。知识卡在任务内打开，不强迫先读长篇百科。

主流程：选歌/原创示例 → 确认结构与和弦 → 选 2–4 小节 → 找落点 → 编配试听 → 跟弹 → 自评/录音反馈 → 保存下一任务。

必须覆盖：无音频、音频解码失败、拍点不稳、调弦不符、未知和弦、输入不合法、无法跨越的手型、麦克风拒绝、低频识别不可靠、网络中断。每种情况都提供明确下一步；例如“此处和弦尚未确认，先练节奏与静音音符”。

学习记录分别保存“知道概念”“琴上找到”“跟音乐做到”“换歌能用”，避免用聊天次数估计技能。

## 8. 架构与可迭代性

建议最初使用模块化单体：Web 前端 + API + 后台音频任务队列 + 关系数据库/对象存储。规模和检索量不足时不必先建多 Agent 系统或复杂向量基础设施。

- 确定性音乐引擎：音高、拼写、和弦集合、拍位、音域、指板和候选指法。LLM 不负责心算这些结果。
- 素材服务：音频资产、用户和弦草图、节拍网格、结构版本与来源。
- 分析适配层：BPM/beat/downbeat/chord/section 模型可独立替换，统一输出证据和版本。
- 教学编排器：根据用户目标与已确认上下文决定下一任务；LLM 解释和提问，输出需过结构校验。
- 知识检索：主题、前置知识、风格、难度、证据等级过滤后检索；定义优先于未经验证的风格说法。
- 学习状态：保存可观察行为，不保存无依据的“天赋”“乐感分”。

核心实体：SongProject、AudioAsset、TempoMap、Section、ChordEvent、InstrumentProfile、NoteEvent、Fingering、Exercise、Attempt、KnowledgeCard、Source、LearnerConceptState。

ChordEvent：`id,startBeat,durationBeats,root,quality,bassNote,source,status,candidates,analysisVersion`。时间以拍为编辑单位，秒数由 TempoMap 映射；不能假设永远恒定 BPM。

NoteEvent：`onsetBeat,durationBeats,midi,velocity,articulation,stringIndex,fret,role,intent`。休止无 MIDI；同音异位不能只存 MIDI，否则无法保留用户指法。

接口建议：`POST /projects`、`PATCH /projects/:id/arrangement`（带 revision）、`POST /fretboard/query`、`POST /exercises/plan`、`POST /attempts`。分析异步返回 jobId，不让音频上传阻塞页面。撤销采用事件或版本快照；模型版本升级不重写用户确认数据。

Agent 输出结构：`observedContext, evidenceRefs, uncertainty, oneTask, demonstration, choices, checkMethod, nextStep`。先调用规则工具再解释；无法支持的判断写明所缺信息。检索内容只作为资料，不作为可执行指令。

## 9. 验证与迭代节奏

阶段 A：本次原型、规则模型、种子知识库；验证用户是否能完成两小节循环。

阶段 B：用 5–8 位目标用户做可用性测试；目标假设为多数人能在 15 分钟内完成主任务，且能用自己的话说明至少一个落点。不是已取得的数据。

阶段 C：加入自带歌曲、手动校正、变速、保存与稳定音频调度；积累经过许可的评测数据。

阶段 D：引入音频分析与录音反馈；按风格、音源质量、速度、音区分别评估，先承诺辅助而非全自动。

关键指标：完整两轮不丢结构的比例、能解释落点的比例、去掉提示后的表现、换歌迁移表现、错误提示率、错误分析纠正成本。满意度/留存作为辅指标。需要与“同样时长只看 TAB/视频”的基线对照，不能用练习次数代替学习效果。

上线前必须有：教师审核的知识条目；数学模型单元验证；未知和弦/斜线和弦/非标准调弦回归；无麦克风流程；音频权限和删除路径；可访问性与不同窗口尺寸检查。

## 10. 素材策略

第一批优先使用原创 8–16 小节素材，每首保留鼓、和声、贝斯独立轨、MIDI、节拍网格和和弦真值。覆盖 straight eighths、shuffle、基础 funk、慢速 ballad，逐步引入转位和小节内换和弦。示例素材的来源和许可与知识来源分开管理。

用户本地歌曲默认只在会话中处理；云端分析应明确告知上传与删除方式。音乐平台链接作为参考元数据，不承诺下载或分轨。公开教材可供阅读不等于可将全文、谱例或音频重新分发；知识库保存原创释义、必要短引和可追溯链接，授权单独核实。
