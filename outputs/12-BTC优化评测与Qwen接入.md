## 1. BTC 优化

没有重新训练或修改权重。原模型架构、170 类词表和官方权重保留，改进推理流程：

1. 整曲连续 CQT 特征，统一真实采样时间轴。
2. 108 帧窗口、54 帧步长，约 10 秒窗、5 秒重叠；重叠部分按中心权重聚合完整 logits。
3. 三帧平滑后使用带转移代价的动态规划解码，不把和弦强行锁定到小节或整拍。
4. 持续至少 0.45 秒的低能量区间才触发门限，门限由音频能量分布计算，没有硬编码当前歌曲的结束时间。
5. 针对开发集低音量失败，增加仅用于模型特征的有上限增益，最高 32 倍；原音频播放和能量检测不放大。
6. 保存全部 170 类分数、top-3、能量、方法参数与版本，便于后续评测和重做解码。分数仍不是校准置信度。

旧实现完整保留在 chords_baseline.py。当前默认为 btc-170-v2，Beat This! 节拍模型保持原版本，播放器同步机制保持不变。

## 2. 独立评测

已部署可回听、可重复运行的评测页面与脚本，8 个开发样本 + 8 个测试样本，每组 70 秒。标签来自预先定义的生成谱，独立于模型输出；测试使用不同根音与合成种子，在参数固定后执行。

| 冻结测试集指标 | 旧版 | 新版 |
|---|---:|---:|
| 全部按时长标签正确率（包含静音） | 73.17% | 80.60% |
| 仅有音乐区间的标签正确率 | 67.62% | 76.58% |
| 静音参考区间正确率 | 100% | 100% |
| 输出区间总数 | 46 | 49 |

新版区间总数没有变少，因此没有把“更少区间”当作评测收益。总体提升主要来自低音量素材；测试中低音量正确率从 0 提高到约 63.85%。大小三和弦、快速换和弦基本不变；大七/sus 组合仅约 9.29%，仍是明显弱项。改善幅度不能外推到真实歌曲。

这套合成集是功能回归与候选方案对照，不是人类听辨标注的真实音乐基准。开发/测试共享合成音色机制，独立程度有限；报告明确保留这个限制。

真实歌曲 manifest 与评分程序已部署，要求审核者、使用依据、完整和弦区间；未审核的条目跳过。当前 **0 首已审核真实歌曲**，用户 MP3 只有节奏/尾段反馈，没有完整和弦真值，所以不计和弦准确率。没有用本系统预测填充“标准答案”。

## 4. Qwen 中文乐理问答

当前实现是真实百炼 Chat Completions 请求适配器，默认模型 `qwen3.8-omni-flash`；使用流式提供商响应，在本机后端收集正文后返回浏览器。当前没有 API Key，所以没有执行真实付费调用，也没有验证账号权限、提供商实际兼容性或回答质量。

可以直接问一般中文乐理；也可选择“当前已确认并保存的和弦”作为依据。后端从保存文件读取事件并检查 revision、确认状态、标签，重新计算构成音，不接受网页随意提供的音名作为真值。

本版只发送：文字问题、最多四张本地知识卡、可选确认事件及构成音。**不上传原音频**，提示词要求不得声称听过歌曲，也不能猜未提供的原曲调性/贝斯音符。提供规则事实、来源与问题来支持回答，不等于模型输出必然正确；知识卡也仍待教师复核。

本地检索是简单的关键词匹配，尚未启用向量检索。模型被要求引用提供的知识卡，服务检查不存在的 K 编号并提示；这不是对所有回答事实的自动证明。前端按文本渲染回答，防止模型输出被作为 HTML 执行。

完成的接入能力：

- 本机隐藏输入 Key 的配置工具，保存位置不在 HTTP 静态目录或分享包中；环境变量优先。
- 状态接口只返回是否配置、模型与说明，不返回 Key/地址。
- HTTPS 官方服务域名限制、禁用携密钥重定向、超时与响应大小限制。
- 401/403/404/429 等错误给出明确提示，不显示提供商原始错误正文，不自动重试收费请求。
- 相同模型/凭据/问题/依据的成功回答在服务进程中缓存，最多 64 项；重启后清空。
- 一个正在执行的问答请求限制，避免连续点击造成多次并行调用。
- 不把未保存或过期校正发送为已确认事实；切换歌曲时旧响应不会写到新歌曲展示中。
- 可以导出已确认并保存的结构化问答依据，不包含音频。
