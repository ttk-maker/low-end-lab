# 当前模型盘点、优化与可选 API 接入

核对日期：2026-11-08。依据 v0.4 实际代码、验证文件，以及本次重新读取的官方模型卡、作者仓库和计费文档。本轮只研究与说明，没有改动运行中的模型、参数或用户校正。

## 当前到底用了什么

当前没有接入大语言模型（LLM），但有两个预训练的专门音频神经网络。它们不是聊天大模型。

| 功能 | 实际实现 | 是否神经模型 / LLM | 费用 |
|---|---|---|---|
| 拍点与小节起点候选 | Beat This! small0，CPU，minimal postprocessor，dbn=False | 专门节拍神经网络；不是 LLM | 本地，无 API 费用 |
| BPM | 检测拍点间距的中位数 | 数值统计 | 本地 |
| 每小节拍数候选 | 相邻 downbeat 中的拍点数量统计 | 规则，非完整拍号识别 | 本地 |
| 段落变化 | 32 个对数频带、左右各 2 秒特征差、0.25 秒探测与峰值过滤 | 信号处理，无神经模型 | 本地 |
| 和弦时间轴 | BTC-ISMIR19 大词表，170 类，CPU | 双向 Transformer 专门识别模型；不是 LLM | 本地，无 API 费用 |
| 和弦构成、音程、指板、练习卡 | BassModel + ChordTheory + 少量已关联知识来源 | 确定性计算与模板；不是 LLM / 自由检索 RAG | 本地 |
| 自动调性/转调、实际低音与贝斯转录 | 尚未实现 | 无 | 无 |
| 音乐理解问答 | 未配置入口与证据导出 | 没有调用音乐大模型 | 无 |

Beat This! 的预测用于测量时间位置，音乐问答模型不应该任意改写这些时间戳。和弦音计算继续使用现有规则，例如 Am7 的 A–C–E–G 是可验证结果；大模型负责将已确认事实解释成更灵活的教学内容。

## 节奏模型：先保留，再对照评测

用户已经确认当前测试音乐拍点准确。当前只说明这首素材达到听辨需求，不代表所有风格都已验证；不应为了“升级”立即改变生产模型。

作者公开 small0/1/2（约 8.1 MB）和 final0/1/2（约 78 MB）权重。可在相同预处理、相同标注集下比较 small0 与 final0 的 beat/downbeat F1、漏拍、半速倍速错误和 CPU 耗时。只有测得稳定收益才切换；文件大小不等于推理速度或准确率保证。

DBN 是可选后处理，不是当前已启用模块。它可作为稳定节拍网格的对照，但可能对变速或不规则节奏引入偏差，且带来 madmom 依赖。Beat This! 本身就是面向不依赖 DBN 的节拍跟踪，不默认“加 DBN 就更好”。

如果后续发现 funk、shuffle、弱起、变拍或低鼓声素材反复失败，可以开展有监督微调：

- 整理合法可用音频，标注每一拍时间与小节第一拍；把“未听清”保留为未审核区域。
- 按歌曲或艺人划分训练、验证、测试，禁止同曲不同片段泄漏。官方已提示公开权重训练集重叠会让评测虚高。
- 从现有权重初始化，以较小学习率训练；建议先尝试少量可训练层，再逐步解冻，属于待验证的工程方案。
- 使用官方已研究的速度、移调、遮挡增强。速度变化须同步变换时间标注；单纯移调不改拍点。
- 比较 beat 与 downbeat 指标，分别统计切分、弱起和变拍。当前素材保留为回归用例，不能作为唯一训练与测试素材。

官方提供训练脚本、标注与特征资料；发布权重去除了优化器状态。因此从公开权重微调时应显式初始化优化器与训练配置，不保证直接用“恢复训练”参数即可无改动续训。模型代码和权重为 MIT，训练音频仍按各自许可使用。

当前界面保存校正只是在保存数据，不会自动训练、在线学习或修改模型权重。

## 和弦模型：当前最值得投入的优化

目前 BTC 支持 12 根音 × 14 性质 + X/N。现有 MP3 输出 25 个候选区间、约 3.25 秒未知，且在约 16 秒后用户已听不到音乐时仍延展出持续和弦。独立合成 C→Dm 测试通过，但没有教师标注的真实和弦真值，不能据此给出真实歌曲准确率。

优先改进推理过程，再判断是否训练：

1. **重叠窗口与聚合。** 当前按不重叠的 10 秒窗口识别，窗口边缘上下文不足可能导致突变。对照 10 秒窗、5 秒步长的方案，在重叠处按中心加权聚合完整 170 类 logits/posteriors，再统一解码；切片时间必须映射回原音频。现有缓存仅保留 top-3，若要重做完整后处理应重新推理并保存完整分数，不能从 top-3 还原缺失类别。
2. **使用连续性和拍点作为软约束。** 当前只有三帧均值平滑，可比较带转移代价的 Viterbi/半马尔可夫解码、最短时长与拍点附近变化的软偏好。不能强制一拍/一小节一个和弦，也不能把快速换和弦全部抹掉。ChordMini 官方已提供 overlap、logit aggregation、Gaussian smoothing、min_segment_duration 等实现参考；其示例 0.5 秒不是适合所有歌曲的固定真值。
3. **声音结束与低能量处理。** 当前 RMS 阈值是最大帧 RMS 的 0.001 倍（幅度约 -60 dB）或 1e-5，较弱尾音仍可能通过。比较分频能量、噪声底估计、持续时间与迟滞门限；保留持续的弱和声，避免把安静段落删掉。不把用户说的“16 秒”硬编码成所有曲目的阈值。
4. **校准未知与置信度。** 目前 0.35 最大分数与 0.08 前两名差只是工程门限。用独立人工标注校准温度与弃答阈值，比较准确率/覆盖率；按大小三和弦、七和弦分别统计。不能靠减少 X 的数量宣称更准确。
5. **与 ChordMini/ChordNet 比较。** 作者已提供 BTC CL、ChordNet CL 等权重，适合同词表对照。没有在本项目测试前，不把新模型自动认定为更好。

确需微调时：

- 数据单位为音频与 `startSec/endSec/chordLabel`，只将人工复核过的事件当标签；未确认区间使用训练 mask，不能一律作负例。
- 按音高移调同步变换根音和人工 bass note，保留和弦性质；按速度增强同步变换区间边界。
- 在既有权重上先训练输出层，再小学习率解冻部分网络；混合旧分布素材减轻灾难性遗忘。
- 对罕见七和弦、半减七、sus 等评估类别权重或 focal loss；不能仅提高常见大小三和弦的平均分。
- ChordMini 有伪标签与知识蒸馏训练路线；伪标签只作为辅助，须过滤并经人工验证，不能用同一教师的预测评价学生真值。
- BTC 的输出空间没有 9/11/13 和弦或斜线转位。单纯继续微调 170 类不会获得这些新类别；需要改标签体系与模型输出，或增加独立低音估计模块。

目前短小模型通常不必优先上 LoRA；标准的冻结部分参数/常规微调更直接。LoRA 是大模型参数高效微调方案，不是对任意音乐模型准确率的保证。所有训练建议都尚未在本项目执行。

## 缺失能力分别适合什么

| 能力 | 建议 | 理由和边界 |
|---|---|---|
| 中文音乐问答、教学 Agent | 首先评测百炼 Qwen3.8-Omni-Flash API | 中文接入方便、本机无须大显存；输入音频与已确认事件，输出带依据的解释。此型号按本次官方文档核实，不与开源 Qwen3-Omni 混用 |
| 音乐领域理解研究 | Music Flamingo 2601，与 Think 版对照 | 官方明确支持和声、结构与 theory-aware 问答，有训练示例；8B 总参数，20 分钟上限，非商业研究许可。尚未验证当前素材与中文准确率 |
| 主歌/副歌等曲式标签 | all-in-one 作为专门结构模型候选 | 输出功能段落标签；不是 LLM，Windows NATTEN 依赖需隔离验证。短片段可能无法判断完整曲式 |
| 和弦音、音程、弦品位置 | 继续现有确定性模型 | 有精确规则，无须用大语言模型替换 |
| 调性/转调 | 先添加专门调性估计与局部和弦一致性评测 | madmom CNN 可作研究对照，但其模型许可为非商业；相对大小调与调式必须允许候选，不能仅让聊天模型口头猜调 |
| 原曲低音与贝斯音符 | 分离声部后评测 PESTO / Basic Pitch | 模型需要提供真实音高和音头；问答模型可解释结果，不能代替转录。来源与边界详见第 08 份报告 |

针对当前电脑（此前检测为 Iris Xe、约 16 GB 内存），API 是音乐大模型问答更可行的首条路线。Music Flamingo 自部署不是“无需 Key 就没有成本”：需额外 GPU/服务器资源；官方测试 A100 80 GB 不等于最低显存要求。8B BF16 权重本身已约 16 GB，另有激活与缓存；量化部署需另测质量和兼容性。

建议的 Agent 输入为：所选音频片段 + 原音频时间范围 + 已确认拍点/和弦及事件 ID + 乐理规则结果 + 检索知识卡 + 学习目标。输出至少包含证据区间、解释、练习与未知项；不能改写用户确认数据。只在提问时调用，缓存结果，优先复用结构化证据，避免反复上传整曲。

接入 API 前先建立固定音乐问答题集比较效果。通用模型的专业口吻、输出 JSON 或更长推理，不证明识别准确。提示词约束、知识检索和工具调用不属于权重微调。尚未核实 Qwen3.8-Omni-Flash 开放客户音频权重微调，因此不能承诺“购买 API 后即可微调该模型”。

自部署 Music Flamingo 官方提供 supervised training/loss 示例。未来可研究冻结音频编码器、对语言层做 LoRA/适配器训练，数据应是教师审核的“音频 + 问题 + 有证据的答案”；具体 PEFT 兼容性与质量尚未在本项目验证。文字答案训练可能改善表达，却不一定修复音频感知错误。

## API Key 与价格

现有 Beat This!、BTC、规则指板与乐理卡均不需要付费 Key。选择百炼音乐问答需开通账号和模型权限，创建与业务空间/地域匹配的 API Key 并按调用量付费；Key 本身不是单独购买的软件许可证。模型费用与其他聊天产品的会员费不是同一账单。

2026-11-08 本次官方计费页列出的 **华北 2（北京）、中国内地部署、非实时 qwen3.8-omni-flash**：

| 项目 | 元 / 百万 Token |
|---|---:|
| 输入 | 0.8 |
| 缓存命中输入 | 0.1 |
| 输出 | 2.7 |

官方调用文档列音频输入约 7 Token/秒。示例：60 秒音频为约 420 Token，另假设文字/知识输入 1500 Token、总计费输出 1000 Token、不命中缓存，则费用约 `(420+1500)×0.8/1e6 + 1000×2.7/1e6 = 0.004236 元`。这是按所列单价和假定用量的算例，不是每次问题的固定价格；长上下文、实际输出、重复调用、地域和模型别名变化会改变账单。以实际账号开通页和响应 usage 为准，不承诺免费额度。

不要把这组非实时价格套到 Omni-Realtime，也不要把 Qwen3.8 价格套到 Qwen3/3.5。Key 只放本机后端环境配置，不放前端或聊天中。采用云端听音频时，所选片段会发送给该提供商；只做结构化文字解释时可不发送音频，但模型就没有直接听到歌曲。

## 推荐优先顺序

1. 保留当前节拍模型，建立更多风格的独立标注评测集。
2. 优化 BTC 的窗口衔接、连续性、声音结束与未知校准，评估 ChordMini 对照。
3. 用已经保存并审核的人工校正积累训练数据，采用版本化离线实验，达标后再切换默认模型。
4. 如愿意使用付费 API，再接 Qwen-Omni 中文音乐问答；继续用专门模型负责时间轴和和弦证据。
5. 有稳定评测集与算力后，再考虑 Beat This!/BTC 有监督微调或 Music Flamingo 研究训练。
