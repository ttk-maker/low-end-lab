## 不能由这些检查证明的事情

- 通过音频 API 和播放状态检查，不等于已经做真人盲听或专业音色验收。
- 本次没有用户访谈、正式可用性测试或学习效果实验；痛点与指标是有资料支持的设计假设。
- 知识卡未经独立贝斯教师审核，不能标记为专家认证。
- SVG 已按原型实际布局生成，但没有在 Figma 云端打开验证；不应声称它含原生组件或已发布设计系统。
- 原型没有真实歌曲的识别结果，因而没有 BPM/和弦识别准确率或录音评分准确率可报告。

## 已知限制

- 当前编辑器只有固定八分格和两种短于八分音符的门限长度；不支持跨格连音、十六分、三连音、swing、滑音或 ghost note。
- 当前每次切换段落/范围载入示例，会替换编辑区；本地保存只保留当前草稿，可用 JSON 导出保留其他版本。
- 根音/五度/连接模板是受约束示例，不保证每个风格都适用，也不是“最佳编配”。
- 暗色指板音与小字号是为密集信息做的折衷，正式版需提供放大、简化音符显示和更大触控区域。
- 当前工作台保持标准四弦调弦；替代调弦在实验室中演示。将乐器配置贯穿所有页面属于下一版。

## 下一阶段建议验收

1. 用本人的一首熟悉歌曲完成手动结构与和弦草图，检验真实工作流；保留未知和弦而不猜造。
2. 请两位贝斯教师独立评审知识卡与模板，记录争议属于事实、风格还是教学顺序。
3. 让目标用户在不受讲解的情况下完成“选段 → 编两小节 → 跟弹 → 解释落点”，记录耗时和卡点。
4. 扩充音符时间模型和持久化，再引入真实歌曲分析。分析结果必须允许校正，并区分候选与已确认。
5. 录音评估只在延迟、信噪比和低频置信度达到门槛后启用；低质量音源应拒评，并仍可继续自评练习。
