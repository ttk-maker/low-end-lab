# LOW END LAB：页面与 Figma 实施规范

版本 0.2 / 2026-11-08。交付形式经用户同意改为本地 HTML 交互原型、SVG 设计页和文字规范；没有创建 Figma 云端文件。SVG 是可导入的静态矢量设计稿，不等同于带 Auto Layout、组件变体和原生交互连线的 .fig 文件。

## 产品视觉方向

深色练琴工作台，面向长时间看屏幕练习。以黄绿色表示当前行动/根音，以蓝、杏、淡紫区分三、五、七音。始终同时显示文本或级数，不能只依赖颜色。界面不铺满聊天气泡；Agent 在右侧只给当前任务。

桌面参考 1440×1024，侧栏 196 px，顶栏 68 px，内容左右 32 px；主工作区与 282 px 陪练栏相隔 24 px。主体从歌曲地图往下依次是和弦/指板、两小节编配、播放器。主要行动随学习阶段变化，避免每个区块都出现抢眼主按钮。

平板 ≤980 px：陪练栏移到工作区下方，保证指板可读。手机 ≤650 px：顶部短导航、歌曲小节分两行、指板局部横向滚动，其他内容禁止整页横向溢出。实际拿琴时优先横屏或平板。原型手机可使用，但正式版需要将小节编辑改为逐小节展开，以提供更大触控目标。

## 页面 01：我的歌曲

目标：迅速进入一段可以开始的音乐。

- 顶部说明“从喜欢的音乐开始”。列表每首只放名称、调性、速度、拍号/长度、当前学习目标。
- 主按钮“继续练习”进入工作台，保留上次范围与音符。
- “选择本地音频试听”真实打开文件选择器；音频只在浏览器播放。原型明确说明不进行自动分析或与编配同步。
- 正式版扩展：添加项目向导，分为音源、调弦、已有和弦/未知和弦、目标段落；保存后进入确认页。处理音频错误、重复导入、无音源与取消。

## 页面 02：练习工作台

目标：在两小节内完成学习循环。

| 控件 | 交互 | 状态/反馈 |
|---|---|---|
| 学习步骤 1/2/3 | 更新右侧任务与示范行动 | 选中态与 aria-selected；不强制按顺序完成 |
| 前奏/主歌/副歌 | 切换示例和弦序列 | 停止当前循环、载入对应示例；明确提示 |
| 小节按钮 | 从该小节起循环两小节 | 当前/下一/正在播放分别表示；末小节可回到段首 |
| 和弦标题 | 随正在编辑的第 1/2 小节变化 | 显示和弦名及构成音；不是识别结果 |
| 音名/级数 | 切换指板标记 | 不改变 MIDI 或和弦事实 |
| 指板音符 | 试听并写入当前选中格 | 白圈表示选择；非和弦音仍可使用 |
| 节奏格 | 选择编辑位置 | 强调选中格，显示弦品与音高；两小节固定八分格 |
| 根音/五度/连接模板 | 替换当前两小节草稿 | 可撤销；明确为规则示例 |
| 休止/音长/撤销 | 编辑音符或恢复上次草稿 | 无音符时解释为何不能改音长；撤销无历史时禁用 |
| 播放/停止 | 循环合成鼓、和声、当前贝斯线 | 显示当前拍；空间键可在非控件焦点下切换 |
| BPM 滑块 | 改变练习速度 | 合成音高不变；50–140 BPM |
| 贝斯开/关 | 隐藏示范贝斯，保留伴奏 | aria-pressed；方便自行跟弹 |
| 陪练主按钮 | 载入当前任务模板并播放 | 不是向真实 AI 服务请求 |
| 知识卡 | 打开解释、琴上任务、来源链接 | 对话框关闭后回到练习 |
| 自评 | 选择一个主要问题 | 保存自评与下一任务，不伪装成机器评分 |
| 保存练习 | localStorage 保存 | 成功/失败状态；失败可导出 JSON |

原型当前换段落或两小节范围会载入新示例并替换编辑区。正式版应按范围独立保存草稿，切换时保留版本。原型的保存仅保留当前草稿，不应视为完整工程版本管理。

## 页面 03：指板实验室

目标：验证“这个位置是什么音，它在这个和弦里是什么角色”。

根音、和弦类型、调弦、显示方式四个控制独立存在。点击指板只选择/试听该音；只有明确按“以所选音为和弦根音”才改根音。这防止用户误以为一处位置能唯一决定和弦。

显示实音 MIDI、频率、弦品、和弦角色以及整个和弦的拼写。支持标准调弦和 Drop D，切换后所有位置重算。工作台与实验室均展示完整 0–21 品；较窄窗口内局部横向滚动，并提供低/高把位跳转。底层模型默认 21 品且允许配置品数。彩色音点文字统一为 #142018、700 字重、12 px，实测对比度为 9.80:1–13.82:1。

## 页面 04：学习记录与知识卡

目标：回到可操作的下一步。

自评条数与当前 BPM 不作为能力评分。展示最近自评和对应下一任务。知识卡提供来源、原创释义、前置知识与琴上练法。导出 JSON 保存草稿与自评，方便迭代或后续迁移。

正式版加入：每个概念的“认识/找到/弹出/迁移”四种证据、间隔复习、教师审核状态；避免未经测量的百分比掌握度。

## Figma 文件组织与重建

建议页面：00 Cover & Flow、01 Foundations、02 Components、03 Desktop、04 Tablet & Mobile、05 States & QA。

将交付 SVG 拖入 Figma，每张为独立画面。SVG 保留矢量形状和文字，但字体替换、分组、语义组件需要检查；不能承诺自动获得 Auto Layout。

原生重建顺序：创建 tokens → Frame 与列布局 → Navigation/Button/SectionTab/ChordBar/FretNote/StepCell/CoachTask/Transport/Dialog → 加状态变体 → 绑定数据 → 建 Prototype 连线。

组件建议：

- Button：primary/secondary/quiet × default/hover/focus/disabled。
- FretNote：root/third/fifth/seventh/other × selected/unselected；数据包含实际音高和拼写。
- ChordBar：idle/current/next/playing/uncertain；文本表示状态。
- StepCell：note/rest × selected/playing；不要将颜色作为唯一输出。
- AnalysisState：pending/candidate/confirmed/user-corrected/failed，供未来真实分析使用。

原型连线：歌曲继续 → 工作台；工作台步骤 → 任务面板状态；小节 → 和弦/指板/编配同步状态；知识卡/自评 → Overlay；导航 → 对应页面。模拟连续播放可用交互原型实测，不必在 Figma 里伪造精确音频引擎。

## 完成标准与边界

本地原型验证信息架构、按钮语义、指板关系、音符编辑、示范播放和自评闭环。它没有接入大模型、音频转谱、麦克风、真实演奏评分、云端数据库或平台歌曲下载。

音频是浏览器振荡器合成，足以比较音高和时值，不代表高品质贝斯音色或真实乐队伴奏。完整产品应换成经过授权的采样/合成器、稳定的音频调度和更细致的节奏表达。
