# v0.6 节奏、小节与按拍和弦精细化

2026-11-08。顺序：检查原始时间轴与编号 → 统一小节数学模型 → 节奏修复与长音频验证 → 按拍和弦与版本保护 → 浏览器回归与部署。

## 查明的问题与修复

截图顶部的 1、2、3 原来是声学段落编号，并不是小节号。已明确写为“段落 1”等；绿色竖线单独显示小节号。

旧播放器用“检测到第几个强拍”决定小节号，最近强拍之后的拍数直接相减。漏检强拍时可能出现一小节超过设定拍数，后面的小节编号也会偏移。现在由同一个 RhythmGrid 提供波形、小节计数、提示音强拍与和弦坐标。固定每小节 M 拍，首拍索引 A（i、A 从 0 计），第 i 个拍点所在小节为 floor((i-A)/M)+1，拍位为 ((i-A) mod M)+1；首拍前按弱起/前置部分显示。

所有位置使用检测或校正后的绝对音频时间，不用显示时四舍五入的 BPM 循环累加。原曲 37 个检测拍点和已有保存结果没有被自动改写。截图本身不能证明原始模型拍点随时间漂移；此次区分了编号错误、时间误差与首拍相位错误。

## 节奏修复与操作

1. 查看“① 校正并锁定节拍与小节”的拍数、疑似漏拍/多拍数量。
2. 回听每小节拍数和第一拍；在第一拍附近暂停，使用“将附近拍点设为小节第一拍”。固定分组支持 2–7 拍。6 拍分组不等于自动识别 6/8；当前不自动推断变拍号时间轴。
3. “检查漏拍 / 多拍”根据局部拍间距和音频起音提出候选。缺少音频起音支持时不补拍；仍有异常会提示，不自动覆盖。
4. 确认是固定速度时，可用“固定速度：全曲拟合”。拟合使用全曲拍点与异常值剔除，保留完整精度；残差过大则拒绝，不拉直明显变速素材。此方法不能解决所有自由速度或误检，候选需回听。
5. “采用此节奏候选”只修改编辑副本，可撤销；回听后“确认节奏并保存”。默认不会将拍点外推到整个静音尾部，最后一拍后的显示范围仅按局部拍长估计，并标记不完整小节。

这次没有微调 Beat This! 权重。没有独立真实歌曲标注时，不能用本模型预测训练自己并声称准确率提升。

## 和弦流程

“② 按小节听和弦”排在节奏校正之后。小节条带按当前节奏切分展示现有和弦；同一个和弦可以跨小节延续，一小节可以有多个和弦。点击小节标题循环回听该小节，点击和弦查看原有确认与指板功能。

锁定并保存节奏后，才可“按已锁定节奏生成候选”。对每个半拍单元，以时间重叠长度加权聚合 BTC 的完整 170 类分数，保留未知判定；连续同类合并。仅声学持续低能量区间固定静音边界，不把模型给出的任意 N 当作真实静音。没有为每小节强制选一个和弦，也不自动把 N 或 X 填成根音。

候选需明确采用与保存，不会自动覆盖人工和弦。半拍单元不能表示所有 swing、三连音、十六分切分和自由时间的换和弦，仍可展开“逐区间编辑与原始时间”保留或调整实际边界。原始 BTC events/rawFrames 保留。

保存按拍和弦时记录其依据的节奏版本。节奏改变后会提示过期，后端拒绝将旧版本作为新的有效按拍校正保存，Qwen 也拒绝过期节奏依据。可以重新生成，或“沿用现有标签，重新核对”：保留标签与时间，但撤销原有确认状态。新增节奏字段向后兼容历史项目。

## 验收与边界

在线报告：http://127.0.0.1:8765/audio-analysis/evaluation/rhythm.html。

实际 Beat This! 推理的合成测试包含 240 秒固定速度、240 秒渐变速度、180 秒三拍 swing。每小节拍数由生成谱给定，不计作模型自动识别。节奏参考来自合成谱，独立于网络预测。

| 测试 | 拍点 F1，±70 ms | 95% 拍点误差 | 自动分组强拍 F1 | 给定首拍后强拍 F1 |
|---|---:|---:|---:|---:|
| 240 秒固定速度 | 99.90% | 21.32 ms | 100% | 100% |
| 240 秒渐变速度 | 99.90% | 20.49 ms | 100% | 100% |
| 180 秒三拍 swing | 99.83% | 25.00 ms | 0% | 100% |

三拍 swing 自动首拍相位错误，是实际失败项，不应隐藏。给定正确首拍索引后，小节计数正确；该指标属于辅助条件。三段均有一个参考范围外的尾部拍点。已匹配拍点的序号错位为 0，各分钟时间误差没有持续增大的趋势。

固定速度拟合的 95% 拍点绝对误差为 12.03 ms；变速片段被拒绝均匀拟合。自动修复在这三段上未改动拍点，不声称 F1 因修复提高。另用人为注入漏拍、缺少起音支持、变速、弱起等逻辑用例检查修复策略。

另一个 24 秒和弦开发回归使用独立合成谱和已知 120 BPM 网格。原始 BTC 与按拍候选的时长标签正确率为 82.36% / 84.12%，边界精确率为 55.56% / 66.67%，边界召回率为 100% / 80%（±0.2 秒）。聚合存在漏检代价，仍会把某些有音乐的和弦判为 N；不是准确率全面提升，也不是真实歌曲或完整端到端基准。

浏览器实际加载 240 秒 WAV，在 1× / 0.5× 下检查 1、60、120、180、238 秒，显示拍位与媒体时钟一致。另验证提示音提前调度、暂停取消、变速重排、尾部停止、波形缓存、保存/撤销、节奏版本过期拒绝及 390 px 布局。没有把跳转检查描述为完整连续四分钟设备延迟测量。

目前仍缺少用户提供的 3–4 分钟真实歌曲及独立人工拍点/和弦参考，不能保证任意风格真实歌曲都满足上述误差。实际验收应覆盖开头、每分钟和结尾，分别检查时间误差、拍序漏检、小节相位和换和弦边界。既有 MP3 仅约 24 秒，不能承担长曲真实验收。

## 复现

- 节奏单元测试：`python -m unittest discover -s audio-analysis/tests -p test_rhythm.py`
- 统一网格与按拍和弦：`node audio-analysis/tests/rhythm-grid.test.cjs`
- 长音频神经网络测试：`python audio-analysis/evaluation/rhythm_long.py --work-dir ../work/rhythm-long --report ../work/rhythm-long-report.json`
- 和弦聚合回归：`python audio-analysis/evaluation/harmony_grid.py --work-dir ../work/harmony-grid --report ../work/harmony-grid-report.json`

Python 使用项目音频虚拟环境；和弦聚合测试还需 Node.js。测试音频可以由脚本再生成，无需上传云端。
