# v0.4 · 和弦时间轴、校正、指板与乐理卡

2026-11-08。按开发顺序完成前三步；第四步按用户选择，保留音乐问答入口，暂不连接外部模型。

## 打开与使用

打开 http://127.0.0.1:8765/#analysis，刷新后侧栏版本为 v0.4。若本地服务停止，双击 `启动音频分析.cmd`。既有节拍与段落功能、21 品指板及练习工作台继续可用。

原音频播放区下面新增“和弦时间轴 → 指板落点”。提供的 MP3 已完成一次真实 BTC 推理；其他已分析歌曲可点击“分析本曲和弦”。整个过程使用本机 CPU，无需账号或 API Key。

1. 点击一个和弦区间，使用“循环所选和弦”及原曲播放按钮回听。点击选择时关闭自动跟随，便于编辑；勾选“跟随播放选择”可恢复。
2. 检查根音、和弦性质；实际低音没有自动识别，可以人工指定。应用标签后状态为待确认。
3. 可移动开始边界、在播放位置拆分、沿用所选标签合并后段；结构变化会撤销受影响区间的确认。
4. 点击“已回听，确认此和弦”，显示标准 E–A–D–G 调弦的 0–21 品指板。绿色是根音，蓝色是其他构成音，橙色边框标出属于构成音的人工低音；点击亮起的音试听。未确认、N 或 X 不生成落点。
5. 查看下方“和弦乐理卡 · 规则计算”，包含构成音、半音数、根音/低音区别与一条练习。
6. 点击“保存和弦校正”。它与原有“保存校正”（节拍/段落）是独立保存。尚未保存的任何一类校正都会阻止切换歌曲。

音乐问答按钮明确显示未配置；确认并保存后，可“导出本段问答依据”，保存区间、和弦、规则解释和知识来源，不包含音频，也不发往外部服务。

## 第一步：真实和弦时间轴

使用作者发布的 BTC-ISMIR19 大词表权重，在 CPU 上执行实际推理。170 类为 12 个根音 × 14 类性质 + X + N。权重约 12.2 MB；来源和许可随包保留。

本曲解码 23.69306 秒，产生 **256 个逐帧输出、25 个候选区间**。其中 X 约 3.25 秒，N 约 3.69 秒。较长候选包括 Am、Am7、D；另有短暂的 E7、A7 等输出。它们是模型结果，不是已经确认的和弦进行；不据此自动确定调性。

模型在 13.90–20.00 秒给出持续 Am 候选。这与用户对约 16 秒后已无可听音乐的反馈需要回听核对，可能受尾音或很低能量内容影响。系统保留原始预测以便审查，用户可拆分后将后段标为 N；没有为了贴合预期改写机器结果。最终约 20 秒起输出 N，其中低能量门限从约 20.19 秒起生效。

原始逐帧结果包括 top-3 标签和未校准 softmax 分数；这些分数不显示为准确率。时间轴用三帧平滑；低于 0.35 的最大分数或前两名差小于 0.08 时输出 X。低能量门限独立输出 N，阈值和方法记录在文件中。门限是工程基线，尚未经过真实歌曲准确率校准。

保留官方 10 秒 CQT 分窗，144 个频率格、每八度 24 格、22050 Hz、hop 2048。将每帧时间映射为真实分窗起点加采样间隔，避免原例程 `10/108` 时间单位的累积偏移；边界分辨率约 93 ms，不宣称毫秒级和弦换拍准确率。

首次直接运行约 79 秒，包含首次特征编译等开销；本次服务端实测约 19 秒。不同机器、缓存和曲目长度会改变耗时。

## 第二步：人工校正与指板

新增 `chords.json` 保存机器输出与独立 annotation，具有自己的 revision。节拍/段落仍保存在既有 `analysis.json`。本次开发前后的原项目文件逐字节相同，SHA-256：

`24e03388cb676164f326fe63690af60411bf05a69bca9f93afd35ab84b6c0f2f`

和弦编辑支持等音拼写、14 类性质、人工低音、边界移动、拆分、合并、撤销、恢复机器候选、保存与 JSON 导出。冲突版本返回 409，避免多页面互相覆盖。

指板来自原有确定性 BassModel；只增加小六、大六、小大七三类，以覆盖 BTC 全部性质。原有练习工作台的 Night Pocket 编配仍为独立示例；没有把原曲候选写入用户已有的贝斯线草稿。

## 第三步：可验证的乐理解释

规则计算确认和弦的音名、音程、半音数，正确处理 C# 小大七中的 B#、C 减七中的 Bbb 等拼写。

例如 Am7 → A–C–E–G，对应根音、小三度、纯五度、小七度。G/B 中根音仍为 G，人工低音 B 是大三度；若指定非构成音低音，卡片说明需要结合踏板/经过低音语境判断，不冒称已确认转位。

练习为“按确认拍点先弹稳定落点，再比较根音与五度类构成音交替”。它明确是练习建议，不是原曲转录。卡片引用已有 K03/K11 知识来源；尚未建设自由检索式 RAG。每条卡片带区间和事件 ID。

## 第四步：音乐问答入口

用户明确选择“暂时没有服务，先交付本地功能”。因此保留未配置按钮与本段证据导出，不调用音乐大模型，不生成伪模型回答。今后可使用 Music Flamingo/Qwen 音乐理解服务，输入已确认事件和知识卡；模型接入仍需单独配置与验收。

## API 和文件

- `POST /api/projects/:id/chords/analyze`：提交和弦任务；重复且版本一致时返回缓存，保留已保存校正。
- `GET /api/jobs/:jobId` / `POST /api/jobs/:jobId/cancel`：沿用任务状态与取消；不强制终止正在运行的单个推理步骤。
- `GET /api/projects/:id/chords`：未分析时 `available:false`，已完成时返回原始事件、原始帧及 annotation。
- `PATCH /api/projects/:id/chords`：`{revision,annotation:{events:[...]}}`；原始事件不覆盖，revision 独立递增。
- `chords.py`：特征、模型、平滑/弃答、数据校验。
- `chords-ui.js / chords.css`：独立和弦工作区。
- `chord-theory.js / theory-ui.js`：确定性解释和未配置问答入口。
- `vendor/btc/`：保留作者网络实现、MIT 许可和修改记录。
- `models/btc_model_large_voca.pt`：校验后加载的官方权重。
- `tests/theory.test.cjs`：可运行的乐理验证；另可运行上级 `fretboard-model.test.cjs`。

权重 SHA-256：`1673d23f8f9a55ae7f9e8b80a51da616debb22675b8d8b67ea6ce0ef37b0ab51`。

第三方代码仅调整相对导入、NumPy 已移除别名及去掉独立训练示例；权重校验后使用限制性加载，保留 strict state-dict 检查。

## 验证与边界

- 真实 MP3 实际推理；8 秒合成 C 大三 → D 小三音频得到 C:maj 与 D:min，两段边界约 3.994 秒；该简单测试不等于真实歌曲准确率。
- 静音不虚构和弦；取消、非法区间、保存冲突有明确处理。
- 浏览器验证当前和弦跟随播放、确认门槛、G/B 区分、88 个弦品位置、循环、边界/拆并/撤销、保存刷新、未保存保护与 409 冲突。
- 168 个根音/性质组合及特殊拼写通过；指板数学模型 100 项断言通过。
- 原有播放/循环、节拍编辑、上传推理、段落编辑、保存刷新和响应式布局回归通过；v0.3.2 提前调度与画布缓存回归通过；pip check 无依赖问题。
- 音乐问答入口、证据导出、待保存时禁用证据导出均已验证。

汇总见 `audio-analysis/chord-validation-report.json`。没有人工标注的真实和弦真值，不能报告当前 MP3 的识别准确率。暂未实现实际低音自动识别、贝斯音符转录、完整调性/转调分析、模型问答或真实音频上的自动编配生成。
