# 乐理分析模型复核与下一阶段接入方案

2026-11-08 · 本次直接读取官方模型卡、作者仓库、标签词表与推理代码。这里是选型与接入方案；除现有 Beat This! 外，以下模型尚未在用户音频上运行，也未据此生成这段歌曲的和弦或调性。

## 结论

优先建设“带时间轴的和弦识别 + 确定性乐理解释 + 音乐大模型问答”。推荐 **BTC 大词表作为可复现基线、ChordMini/ChordNet 作为升级评测对象、Music Flamingo 2601 作为音乐理解研究首选、Qwen3-Omni 作为中文问答对照**。不能以一段专业的音乐描述替代逐段和弦识别。

对贝斯手，系统必须分开记录和弦根音、实际低音和可选落点。例如 G/B 的根音是 G，低音是 B；如果识别器只支持 G，它不能凭空生成斜线低音。确定和弦以后，音名、构成音和 0–21 品位置由现有数学模型计算，不让语言模型凭记忆填写。

## Music Flamingo 的新增核实

本次成功读取 `nvidia/music-flamingo-2601-hf` 和 `nvidia/music-flamingo-think-2601-hf` 官方模型卡。更新此前“未读到 2601 官方资料”的结论：

- 2601 模型卡标注 **8B 总参数**，解码器基于 Qwen2.5-7B；不要把解码器参数当成整个模型大小。
- 输入按 30 秒窗口处理，2601 文档上限为 **20 分钟**。旧 `music-flamingo-hf` 的 Usage 写 10 分钟，旧卡后文又写 20 分钟；应固定具体 checkpoint 与 processor 配置，不能混用版本限制。
- 新版类名为 `MusicFlamingoForConditionalGeneration`，旧版示例使用 `AudioFlamingo3ForConditionalGeneration`。已读取 Transformers 主分支的新类实现；模型卡仍残留“等待合并”的说明，所以部署时必须固定并验证库版本，不能照抄旧环境。
- 普通版与 Think 版均明确 **non-commercial research only**。它们适合当前个人研究验证；面向商业产品发布前应更换适当许可模型或另获许可。
- 官方测试硬件是 A100 80 GB，支持环境列 Linux / NVIDIA A100、H100。这不是最低显存需求。只按 8B 的 BF16 权重估算也约 16 GB，尚未计入激活与缓存。
- 本机检测到 Intel Iris Xe、约 15.7 GiB 系统内存，没有检测到 NVIDIA 显卡。当前不把本机完整部署此大模型作为可靠路线；先把小型和弦识别落到本地，大模型后续使用独立 GPU 服务或合适 API。
- 官方卡语言标注为 en；中文教学能力需要实测。可以让音乐模型产生带证据的英文分析，再用中文教学层解释，但翻译不得擅自增加和弦事实。

官方模型卡声明的任务覆盖，证明它确实面向音乐理解；它没有证明对当前 23.69 秒片段能准确给出完整和弦与贝斯线。Think 版本也不能仅凭名字判断更准确。

## BTC 的和弦覆盖，为什么对贝斯有用

作者 `utils/mir_eval_modules.py` 的大词表明确为：12 个根音 × 14 类和弦 + X + N = 170 类。

14 类是 `min, maj, dim, aug, min6, maj6, min7, minmaj7, maj7, 7, dim7, hdim7, sus2, sus4`。这已覆盖 Am7、Fmaj7、G7、Bm7♭5 等常见练习需要；不是只分“大调/小调”。`N` 表示无和弦，`X` 表示词表不能表示的标签，均不能粗暴变成一个根音。

没有 9/11/13 和弦、完整转位或任意 slash chord 标签。必须把“识别标签的能力边界”显示清楚，不能让大模型自动补成它实际上没有识别的复杂和弦。

源码有 CPU 分支，仓库包含 `btc_model.pt` 和 `btc_model_large_voca.pt`。仓库许可 MIT；重新分发时保留许可并核对具体权重来源。ChordMini 也有 MIT 仓库许可与三个 checkpoint，适合同词表对比。本轮只核实来源、代码和文件存在，未下载这些权重进行推理。

## 建议的下一次开发切片

1. **和弦时间轴。** 独立环境运行 BTC 大词表，读取当前音频，输出 `startSec/endSec/label/source/modelVersion/status`。保留原始逐帧预测和平滑后区间；低信息或静音片段允许 N/未知，不强制赋和弦。
2. **循环校正与指板联动。** 在已有播放时钟上显示“当前候选和弦”；点击区间循环，允许改根音/性质/起止位置，确认后显示和弦组成与 0–21 品位置。每小节可以有多个和弦，不能强行一小节一个。
3. **确定性乐理卡片。** 例如确认 Am7 后计算 A–C–E–G、根/小三/五/小七；区分“构成音”“当下可用落点”“需要语境的经过音”。这部分无需等待大型音乐模型。
4. **模型对比。** 同音频、同预处理、同一批教师标注运行 BTC 与 ChordMini，按表现选择默认模型，保留备选而非把多个不一致结果平均。
5. **音乐问答。** 单独部署 Music Flamingo 2601 研究服务，或选适当 API，与 Qwen3-Omni 做相同问题盲评。输入音频 + 已确认事件 + 知识卡；输出要引用区间与事件 ID，不能改写用户确认。
6. **贝斯声部。** 后续加入分离，再比较 PESTO 与 Basic Pitch；先解决音高/八度/音头，再推演指法。同音异位是指法候选，不是音频能直接测出的事实。

推荐顺序是 1→2→3，得到能真正辅助 jam 的最小乐理功能；随后 4→5→6。大模型问答的接入不应阻塞和弦构成、指板落点这些可验证能力。

## 评测应回答什么

- 和弦：按时间加权比较根音、大小三和弦、七和弦层级，分别报告；另测边界误差，不能用“回答很专业”当准确率。
- 低音：专测根音与 bass note 不同、踏板音、连接音；记录八度错误、onset 偏差、ghost note 弃答。
- 调性：相对大小调、调式与转调要分开；很短片段允许多个候选，不能全曲唯一标签覆盖一切。
- 曲式：变化边界与功能标签分开评估；电子音乐的 drop 不强行叫副歌。
- 音乐问答：固定音频、提示词和模型版本，检查每个可验证事实；允许“不足以确定”。模型自报把握不是校准置信度。
- 第一批至少包含明确的大小七和弦、sus、转位、切分、慢速长音、失真和静音。合成素材可验证流程，真实风格片段仍需教师标注。

当前用户音频继续作为端到端回归素材，但没有人工和弦真值，不能据它单独宣布模型识别准确。
